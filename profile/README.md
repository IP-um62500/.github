<h2>一、IP 池由哪三层组成</h2>
<p>入口层接请求，负责鉴权、限速与日志。调度层按策略挑出口，维护每个出口的健康状态与会话绑定。出口层是实际的住宅地址，可以是自建线路，也可以是采购来的代理。</p>
<p>三层分开的好处是各层能独立扩容。入口吃处理器，调度吃内存，出口吃带宽与地址。瓶颈在哪一层就加哪一层。</p>

<h2>二、出口来源的三种选择</h2>
<p>自建是把住宅宽带接到自己服务器，地址最干净，但受线路数量限制，扩不出规模。采购是买代理，快但质量参差。混合是自建打底、采购补峰值。</p>
<p>规模小的时候自建划算，超过二三十个地址后，运维成本会超过采购成本。多数团队最后停在混合模式：核心业务用自建，临时需求用采购。</p>

<h2>三、调度策略怎么选</h2>
<p>轮换适合无状态的抓取，每个请求换一个出口，最大化分散。粘性适合需要连续会话的业务，同一任务固定一个出口直到结束。按权重适合出口质量不均的情况。</p>
<p>实际系统里常把三种叠起来：任务级粘性，任务内按权重选出口，任务结束后释放。这样既保证会话连贯，又让质量好的出口承担更多流量。</p>
<h3>会话保持怎么做</h3>
<p>给每个任务生成一个编号，调度层用哈希把编号映射到出口，并记录过期时间。出口失效时重新映射并记录一次切换，切换次数要能被统计出来。</p>
<h2>四、服务器配置分步做</h2>
<p>第一步装系统，选长期支持的版本，关掉用不到的服务。第二步配静态内网地址与防火墙，只放行必要端口。第三步装调度程序，先跑单机版验证逻辑。</p>
<p>第四步接入出口清单，按格式导入地址、端口、账号、地区四个字段。第五步压测，用固定并发跑十分钟，看错误率与延迟分布。第六步才接真实业务。</p>

<h2>五、健康检查与剔除</h2>
<p>检查分主动与被动。主动是定时向每个出口发探测请求，看响应码与耗时。被动是统计真实请求的失败率，连续失败超过阈值就临时剔除。</p>
<p>剔除要有恢复机制，否则一次抖动会把好出口永久踢掉。常见做法是冷却期内不分配流量，冷却结束后放少量流量试探，通过再恢复全量。</p>
<h3>阈值怎么定</h3>
<p>失败率阈值按业务容忍度定，抓取类可放宽到两成，登录类要收紧到一成以内。探测频率不宜过高，每分钟一次足够，太频繁本身会被注意到。</p>
<h2>六、监控、扩容与成本</h2>
<p>监控看四个指标：出口可用率、平均延迟、错误码分布、每出口流量。可用率下降先看上游，延迟上升先看跨境段，错误码集中说明在限流。</p>
<p>扩容按瓶颈走。连接数打满加内存并调文件句柄数，带宽打满加线路，地址被封加出口。盲目加机器而不看瓶颈，钱花了问题还在。</p>
<h2>常见问答</h2>
<h3>静态住宅 IP 池最少要多少个地址才够用？</h3>
<p>答：看并发与目标站点。单站点低频抓取，五到十个就够。登录类按主体数一比一配。限流严格时，地址数按并发上限反推。</p>
<h3>池子里的地址需要定期更换吗？</h3>
<p>答：出现可用率下降、验证码增多、同段其他用户行为异常时换。没有异常不必频繁换，频繁更换会让使用记录断裂，不利于排查。</p>
<h3>自建池和买代理池哪个更适合小团队？</h3>
<p>答：十个地址以内，自建可控且长期便宜，但要有人会运维。没有专职运维的小团队，买现成的池子更省事，代价是单价高、质量依赖上游。</p>
<h3>调度层用单机够吗？</h3>
<p>答：几十个出口、每秒几十个请求的量级，单机足够。到每秒数百请求或需要高可用时，才需要多机加共享状态，否则单点故障会拖垮整个池。</p>
